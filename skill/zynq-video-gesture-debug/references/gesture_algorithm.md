# PL 手势算法调试

## 处理链

推荐把处理链分成可单独观察的阶段：

```text
RGB888
-> YCbCr
-> 肤色阈值
-> 形态学/去噪
-> 手部包围框
-> 扫描线连续肤色块
-> 手指数、指缝、握拳
-> 中心坐标与深度
```

每个阶段都应有 ILA 可观察信号，否则只能凭串口结果猜问题。

## 手指计数

扫描线上的连续肤色块可作为手指候选。缝隙判定应相对于当前手指或肤色块宽度：

- 小缝隙按阴影、反光或肉褶填平；
- 超过约半个手指宽度的缝隙才视为两根手指之间的真实间隔；
- 达到手指块较大比例时才停止计数；
- 帧尾统一提交结果，避免同一帧内跳变。

`zero_cnt` 很适合区分“一直没有肤色”和“刚遇到短缝隙”。如果 `zero_cnt` 恒为 0，先检查扫描线条件、`box_skin_flag` 和坐标范围，而不是继续调阈值。

## 握拳判定

不要只使用固定像素宽度。更稳健的特征包括：

- 最大连续肤色块相对手部框宽度的比例；
- 独立块数量；
- 扫描线上肤色覆盖比例；
- 食指/拇指方向的附加扫描；
- 连续多帧一致后才切换状态。

远处手部在画面中更小，固定宽度阈值会更容易判成握拳。应使用 `current_finger_width`、`box_width` 或肤色像素总数进行归一化。

## 中心与深度

- 中心坐标应来自稳定手部区域的质心或包围框中心，不应直接用单个像素点；
- 手部丢失时应输出无效状态并清零，不能锁存上一帧；
- “深度”若由二维面积或包围框尺寸估计，应明确它是相对深度，不是毫米级真实距离；
- 映射到 LCD/机械臂坐标时，先验证坐标方向，再调增益和偏移。

## 调参顺序

1. 固定摄像头曝光、白平衡和灯光；
2. 查看肤色二值图；
3. 确认包围框覆盖完整手部；
4. 只看一条扫描线验证手指块；
5. 调整缝隙阈值；
6. 加入握拳判定；
7. 最后做坐标和深度映射。

一次只改一个参数，并分别记录近、中、远三个距离的图像和串口结果。

## 常见误判

- 背景中木色桌面被判为肤色；
- 手部过曝形成孔洞；
- 袖口形成额外连通域；
- 指缝被填平，手指数恒为 1；
- 远处手指宽度小于固定阈值，被误判为握拳；
- 手离开画面后状态和坐标仍保持上一帧；
- 只在 UI 代码中清状态，PL 仍输出旧值。
