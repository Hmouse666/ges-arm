# PS 与 STM32 通信排查

## 单一协议真值

PS 输出结构体和 STM32 解析结构体必须逐字段一致。至少核对：

- 字段顺序；
- 类型宽度；
- 有符号/无符号；
- 字节序；
- 帧头、帧尾或分隔符；
- 校验方式；
- 发送周期；
- 无效帧处理。

本项目对话中曾使用任务号、手势状态、手指数量、X、Y、深度的组合。修改字段时，不能只改打印字符串；必须同步 STM32 parser、任务状态机和上位机日志。

## 串口不通

按以下顺序检查：

1. PS 使用的 UART 编号和引脚复用；
2. TX/RX 是否交叉；
3. 波特率、数据位、校验、停止位；
4. 串口工具是否打开正确 COM 口；
5. PS 是否真的调用发送函数；
6. STM32 中断和环形缓冲是否运行；
7. 是否被调试器、终端或其他程序占用。

“初始化成功”不等于“数据已发出”。应在发送函数入口增加一次低频、不可刷屏的计数日志。

## 发送频率

手势坐标需要实时性，但串口打印会增加阻塞。建议：

- 控制数据按约 20 ms 周期发送；
- 调试文本降频到 200–500 ms；
- 发送函数不等待完整 UI 刷新；
- 避免在 LVGL 回调中执行阻塞式长打印。

## 任务按钮与状态

- 任务选择应在按下时切换；
- 离开屏幕后仍保持当前任务颜色可采用任务锁存；
- 保存锁存状态与保存触摸原始按下状态必须是两个变量；
- 手部撤离时清除手势有效性，但不要自动清除已选择的任务；
- 只有切换到其他任务时才清除上一任务。

## 闭环与安全

- 手部丢失、坐标无效或深度无效时，应停止跟踪或进入安全状态；
- 电机方向、速度、行程和夹爪角度需要独立限幅；
- 不要用 UI 的刷新频率推断控制周期；
- 实测闭环前先做开环方向、限位和急停验证。

## 调试记录格式

建议串口保留一行结构化信息：

```text
[GESTURE] task=1 fist=0 fingers=3 x=412 y=268 depth=149 valid=1
```

字段名比固定中文格式更适合脚本解析。若比赛要求特定显示格式，可另外保留人类可读文本，不要混用两套解析规则。
