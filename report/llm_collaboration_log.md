# 大模型协作记录

## 1. 协作目标

本项目在开发过程中使用大模型辅助完成工程检索、Vivado/Vitis 报错定位、PS-PL 接口排查、LVGL 界面开发、GT911 触摸恢复、手势算法参数调整、STM32 串口协议和 Git 状态恢复。大模型输出作为调试候选方案，最终以综合结果、ILA、串口日志和实机现象为准。

## 2. 主要阶段

### 阶段一：参考工程与开发路线

- 对比 Zynq-7020 手势识别与 OV5640/OV7725 参考工程；
- 确定从“摄像头采集 + HDMI 显示”开始，再逐步加入帧差、手势识别、LCD/LVGL、STM32 控制；
- 明确 PL 负责像素级预处理，PS 负责设备、界面和任务调度。

### 阶段二：视频链路

- 排查 OV7725 初始化成功但 HDMI/LCD 无图；
- 检查 VDMA MM2S/S2MM 数据宽度、帧缓存地址和启动顺序；
- 修正 AXIS 两端 `FREQ_HZ` 与 `CLK_DOMAIN` 不一致；
- 通过 ILA 观察 `tvalid/tready/tlast/tuser`；
- 将原始图像通路与 LVGL LCD 通路拆分为两路 VDMA。

### 阶段三：触摸与 LVGL

- 将 SCCB 和 GT911 都放在 EMIO GPIO 上模拟 I2C；
- 修正 GPIO 方向切换、ACK、坐标寄存器读取和状态清零；
- 完成 GT911 配置下载、坐标读取和触摸映射；
- 修复 Vitis 注释乱码、头文件路径和 LVGL 图片数组格式；
- 完成主页、启动动画、任务按钮、状态提示和透明图片；
- 将按钮事件由不可靠的单击事件调整为按下/释放状态逻辑。

### 阶段四：PL 手势算法

- 从帧差与肤色分割开始提取手部区域；
- 增加包围框、扫描线、连通域宽度和指缝计数；
- 将固定缝隙阈值改为随当前肤色块宽度自适应；
- 增加握拳判定、中心坐标、深度和调试探针；
- 排查“手远时容易误判握拳”，确认固定像素阈值不适合不同距离。

### 阶段五：PS 与 STM32 通信

- 统一 UART0/UART3 调试输出与下位机协议；
- 去除多余串口通道，仅保留实际使用的通信链路；
- 修正任务编号、手势状态、坐标、深度和手指数的打印格式；
- 处理 STM32 任务状态锁存、夹爪状态和释放延迟；
- 检查下位机对协议字段变化的兼容性。

### 阶段六：工程整理

- 将 Vivado/Vitis/STM32 有效源码拆分为 `src/fpga`、`src/ps`、`src/stm32`；
- 将工程生成物与源码分离；
- 保留 XSA 与最近一次实现报告；
- 所有工作树文件名和目录名规范化为小写；
- 增加命名校验与重建脚本。

## 3. 关键经验

1. **先验证数据通路，再修改算法**：摄像头、VDMA、VTC、HDMI/LCD 任一环节错误都会表现为“算法无输出”。
2. **时钟域优先于采样逻辑**：AXIS 两端的 `FREQ_HZ` 与 `CLK_DOMAIN` 不一致时，不能靠修改软件规避。
3. **触摸问题要区分电气与协议**：I2C ACK 正常不代表坐标寄存器读取正确，还要检查配置版本、X/Y 范围和状态位清零。
4. **算法阈值必须尺度归一化**：不同距离下同一手势的像素宽度不同，固定阈值会产生明显误判。
5. **生成物不要纳入源码仓库**：Vivado/Vitis 生成目录不仅体积大，还会因机器路径和工具版本不同导致不可复现。
6. **协议修改必须同步两端**：字段顺序、字节序和发送频率变化后，应同时验证 PL 调试口、PS 打印和 STM32 解析。

## 4. 验证边界

大模型不能替代以下验证：

- 板级电源、电平和引脚连通性测试；
- Vivado 综合、实现、时序和 DRC；
- ILA 实际抓波；
- 摄像头、LCD、HDMI、触摸和电机实机测试；
- 机械臂行程限位与安全测试；
- STM32 烧录后的长时间稳定性测试。

本仓库中的构建脚本和报告用于复现与追溯，最终结论应以实际工具输出和上板结果为准。
